# Private RSA timing advisory and backend remediation

RUSTSEC-2023-0071 / CVE-2023-49092 is a **true positive** for the previous implementation, not a false positive: `RsaOaepCipher::decrypt` invoked RustCrypto `RsaPrivateKey::decrypt`, and hybrid decryption, async consumers and CLI operations reach that method. A consumer exposing chosen-ciphertext operations with measurable timing could expose private-key material. The [RustSec advisory](https://rustsec.org/advisories/RUSTSEC-2023-0071.html) explicitly records no fixed stable `rsa` version; OAEP and a local CLI default do not justify declaring every library consumer safe.

The private OAEP operation now uses maintained **aws-lc-rs 1.18.2 / aws-lc-sys 0.46.0**. AWS-LC imports a temporary PKCS#8 key document and performs private decryption with its native implementation. The existing **OAEP SHA-512 / MGF1 SHA-512** parameters, empty label, supported 2048/3072/4096-bit keys, ciphertext lengths and public Rust key/serialization APIs remain intact. RustCrypto remains for key generation, codecs and public encryption; its affected private decrypt/sign operations are no longer invoked by FluxEncrypt. The DER SecretDocument and temporary plaintext buffer zeroize on drop. Backend failure details are normalized to one cryptographic error for valid-length ciphertexts; a public ciphertext-length mismatch retains the existing input error.

This adds a maintained native cryptography dependency: a C compiler and CMake are needed, plus Perl on build paths that require generated assembly. Container builders install these tools. Static images continue to link the maintained Alpine musl archive and must pass the same link-map/static PIE checks; `aws-lc-sys` statically includes its maintained vendor implementation. The documented 2048/3072/4096-bit RSA capability and its existing ciphertext format are retained. AWS-LC accepts 2048–8192-bit standard private keys; nonstandard raw keys outside its accepted range return a generic error and never fall back to the affected RustCrypto private implementation. The raw compatibility accessor remains available as documented below.

The upstream package advisory remains in inventory because the public compatibility types still depend on `rsa`; the configured audit/deny exception is narrowed to these permitted uses and linked to this record. The source guard `scripts/check-rsa-scope.py`, its negative controls and the local/hosted security gates reject the former RustCrypto private call chain and private-operation imports. This guard is a regression control, not an exhaustive call-graph or constant-time proof.

**Public raw-key accessor boundary:** `PrivateKey::inner()` still exposes `&rsa::RsaPrivateKey` for API compatibility and is documented accordingly. Consumers invoking raw RustCrypto decrypt/sign operations themselves remain affected; they must use FluxEncrypt's `RsaOaepCipher::decrypt` or another maintained backend. This remediation must not be presented as a fix to the upstream `rsa` crate or a universal FP for applications carrying it. No signing operation is implemented by FluxEncrypt.

Validation includes cross-backend OAEP-SHA512 public encryption/private decryption, explicit rejection of SHA-256/MGF1 ciphertexts, uniform error text for malformed in-range/out-of-range/tampered ciphertexts, existing roundtrips/key-format/hybrid/async/CLI tests, all feature combinations, MSRV and native images on both shipped Linux architectures. Timing thresholds in a unit test would not establish absence of side channels and are not used as such a claim. The maintained backend's private-operation implementation and review are the security basis; compatibility tests establish the preserved protocol behavior.

Primary references: [AWS-LC RSA API](https://aws.github.io/aws-lc/rsa.h.html), [aws-lc-rs private decryption key API](https://docs.rs/aws-lc-rs/1.18.2/aws_lc_rs/rsa/struct.PrivateDecryptingKey.html), [RustSec advisory](https://rustsec.org/advisories/RUSTSEC-2023-0071.html). Follow-up: when a fixed stable RustCrypto RSA release exists, reevaluate public compatibility types and remove the exception only after package and call-path validation.
