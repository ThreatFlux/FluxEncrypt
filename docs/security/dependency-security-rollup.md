# Dependency and code-scanning rollup

Reviewed 2026-10-21. Source: all 190 open GitHub code-scanning alerts, retrieved with API pagination; zero open pull requests. Scope is each original scanned artifact, not automatically the current source tree. Rust stable was independently verified from the official distribution manifest as 1.99.1 (2026-10-15). Consumer MSRV remains 1.97.1.

## Implementation and validation boundaries

- Updated Rust compiler/toolchain and CI references to 1.99.1; refreshed direct dependencies and Cargo.lock to the latest stable versions compatible with the public cryptography API. `rsa 0.9.10` is the current stable RSA release; pkcs8 0.10.2, sha2 0.10.9 and rand 0.8.8 must retain its DER/digest/rand_core trait families. The newer incompatible lines are not silently substituted into cryptographic primitives. No prereleases were selected.
- Replaced the Debian shared-library runtime with a static Alpine-musl-linked encryption CLI plus static tini in scratch, for both Dockerfile entrypoint names. This CLI encrypts local files and has no system TLS, DNS or dynamically loaded native engine requirement. All features remain enabled. The linker map must prove `/usr/lib/libc.a` from maintained Alpine, excluding Rust's bundled libc. ELF checks reject PT_INTERP or DT_NEEDED and require a static PIE. Native archive versions/hashes are retained in `/usr/share/doc/fluxencrypt/native-build.txt`.
- This removes the affected Debian OS packages from the replacement runtime rather than claiming Rust upgrades fix glibc or zlib. All-severity Trivy results are retained, including UNKNOWN and LOW; no global ignore was added. Existing public RSA timing advisory RUSTSEC-2023-0071 still has no stable crate fix and must be considered separately from OS-package removal.
- Validation results are recorded below after execution. Historical registry SHA tags for the two old commits were unavailable during review, so original image contents were not reconstructed from unrelated images. Package presence/version in the original artifacts comes from GitHub's scanner evidence, not independently exported old images. App exploitability is not proven by package matching.
