# Dependency and code-scanning rollup

Reviewed 2026-10-21. Source: all 190 open GitHub code-scanning alerts, retrieved with API pagination; zero open pull requests. Scope is each original scanned artifact, not automatically the current source tree. Rust stable was independently verified from the official distribution manifest as 1.99.1 (2026-10-15). Consumer MSRV remains 1.97.1.

## Implementation and validation boundaries

- Updated Rust compiler/toolchain and CI references to 1.99.1; refreshed direct dependencies and Cargo.lock to the latest stable versions compatible with the public cryptography API. `rsa 0.9.10` is the current stable RSA release. Redundant older direct PKCS#8, digest and RNG dependencies are removed; RSA-compatible traits come from its upstream reexports, and key generation/public encryption use its OS CSPRNG. Older trait-family versions remain only where its upstream implementation requires them transitively. No prereleases were selected.
- Replaced the Debian shared-library runtime with a static Alpine-musl-linked encryption CLI plus static tini in scratch, for both Dockerfile entrypoint names. This CLI encrypts local files and has no system TLS, DNS or dynamically loaded native engine requirement. All features remain enabled. The linker map must prove `/usr/lib/libc.a` from maintained Alpine, excluding Rust's bundled libc. ELF checks reject PT_INTERP or DT_NEEDED and require a static PIE. Native archive versions/hashes are retained in `/usr/share/doc/fluxencrypt/native-build.txt`.
- This removes the affected Debian OS packages from the replacement runtime rather than claiming Rust upgrades fix glibc or zlib. All-severity Trivy results are retained, including UNKNOWN and LOW; no global ignore was added. The independently confirmed private-RSA timing TP is additionally remediated through the maintained AWS-LC backend; see [the exact call-path and compatibility boundaries](rsa-advisory.md).
- Validation results are recorded below after execution. The original 7e104c9 GHCR image was recovered by immutable platform digests and independently exported on both amd64 and arm64. The older 161ba96 workflow scanned a Docker Hub release image; its source-version tag 0.7.4 is no longer available there. The 159 older findings therefore retain explicit historical-component uncertainty. Package/source matching alone does not establish application exploitability.
